## 1. 用户与场景

CATIA V5 机械设计人员。日常大量做倒圆角，零件多为**轴对称件**（如矩形板、内外两圈轮廓的框类件）与**回转体**。
核心痛点：**对称位置的圆角要"左边点一下、右边点一下"**，非常累且容易漏；此外常**误选到面**（CATIA 只认手动点选）。

## 3. 已验证的技术事实（务必遵守，别再重复试错）

1. **命令运行中，用户点选的对象不进 `Document.Selection`**（`Count2 = 0`）——不要用它判断"用户选了什么"。
2. **交互式命令不接受脚本加入的对象**：用 `Selection.Add` 加进去的边，对话框列表仍为空；用真实鼠标点「确定」也不生效。
3. 对话框列表里能读到点选单元名：`凸台.1\目标边线.N`；用 `FindObjectByName` 可解析成**可量测单元**（长度 + 采样点）。
4. **关键技巧**：把该**单元对象本身**放进选择集，`SelectedElement.Reference.DisplayName` 会给出**完整真实 BRep 标签**（`REdge:(…Sketch.1;5…Sketch.1;6…)`）；包成 `CreateReferenceFromObject` 再读则是**空**。
5. **BRep 编号 ≠ 草图元素名编号**：`Sketch.1;N` 按**闭合环顺序**编号，`直线.N` 按创建顺序；**每一圈各有一个循环位移**（实测：外圈 +3、内圈 +2）。
6. **引用生命周期**：命令运行中造的引用带 `WithTemporaryBody`，**命令一关即失效** → 必须"先关命令，再造引用"。
7. **跨线程**：气泡按钮回调跑在新线程，必须 `CoInitialize`；不要复用别线程的 COM 指针（每次重新取 `ActivePart`）。
8. **体积自检只能作为下限判据**：对话框开了"相切传播"时体积变化会远大于"两条边"的估计，不能因此撤销。
9. ~~**自动化无法枚举实体全部边**~~ **【2026-09-25 更正，本条原结论错误】**：
   失败的是 `Type=Edge,all` / `Topology.Edge,all` 这类**语法**，不是 CATIA 没有这个能力。
   实测**可用**语法是 **`Topology.CGMEdge,sel`**（配合 `Selection.Add(MainBody)`），
   V5R20 上对 100×60×40 凸台正好返回 12 条三维边，且每条都能 `GetMeasurable` 量长度/半径/采样点，
   拿到的 Reference 还能**直接作为 Fillet 输入** → **形状级对称用纯 Automation 即可实现，不需要 CAA**。
   注意两点：不选任何东西的 `,all` 会混进草图/线框单元（类型名带 `MonoDim`、标签含 `Wire`），必须过滤；
   个别边的 `GetPointsOnCurve` 只回 2 个点（半条边），需要"端点+方向+长度"补全。
   证据：`docs/R5可行性实测-20260925.md`、`docs/R5形状级对称-设计与实现.md`。
10. **NEVER 试探建模**：曾用"探针圆角 + 量体积"识别边，因删除失败（comtypes `_iid_` 报错）在用户模型里堆出 `倒圆角.13…27` 并触发拓扑报错——此路永久禁止。

## 5. 关键算法（自动化版，已实测有效）

1. 读对话框里点选单元 → `FindObjectByName` → `Measurable` 得到**长度 + 采样点**；
2. 该单元对象本体放入选择集 → 读出**真实 BRep 标签** → 与本侧几何编号对比 → 得到**本圈的循环位移**；
3. 用特征草图参数推算**该特征全部候选边几何与标签**（按环分圈）；
4. 用几何（镜像后）匹配出**对称边候选**；再对源边/对称边标签**同圈内位移修正**；
5. 判据：跨圈方案跳过；目标边"到零件中心距离"与源边一致（>5% 或 >1mm 否决）；子段匹配允许被圆角削短的边；
6. 生成前：先读对话框半径 → **先关命令**（避免临时体引用失效）→ 再造两条边的引用 → `AddNewEdgeFilletWithConstantRadius` + `AddObjectToFillet` + `Part.Update`；
7. 体积下限校验（<25% 预期则撤销）；所有分支必须有 `log.exception` + 用户可见提示。

## 6. 完整提示词（可直接复制给下一个 AI）

```text
【任务】为 CATIA V5 开发一个「倒圆角助手」，最终交付可拷贝部署的助手软件（Windows）。

【背景与必须解决的痛点】
1) 设计人员做倒圆角时，对称位置要"左边点一下、右边点一下"——这是最核心的痛点，必须做到"只点一条边，另一条自动补上"。
2) 常误选到面（CATIA 只认手动点选），需要立刻提醒。
3) 特征树要干净：一个倒圆角特征里同时包含"我选的边 + 它的对称边"。
4) 第一刀圆角之后的新形状可能又是轴对称体，要在"新形状"上继续找互相对称的边（形状级对称，不只是草图级）。
5) 圆角会把相邻边削短，必须能连续做第二、三刀，不能因此失败。
6) 换零件必须能用：禁止写死"某零件的编号偏移"，一切现场推导。
7) 部署要简单：目标机不装 Python、不联网，拷贝即用；封闭平台禁止 exe 从临时目录运行时要有第二种打包。
8) 要有退出入口和卸载入口，卸载二次确认。
9) 尽量兼容 CATIA 旧版本：对话框标题、命令 ID、类型库路径都可配置，并有诊断自检。
10) 绝对禁止在用户模型里做"试探性建模"（历史上因此堆出几十个废特征）。

【已尝试过的方式与结果（记录事实，不限制你选别的方案）】
已验证可行的做法（可继续沿用）：
- 自动化（Python + comtypes + pywin32 + Win32 钩子）+ 便携 exe 打包；现已能：误选面提醒、点一条边自动补对称边并生成**一个**含两条边的倒圆角、
  连续多刀、换零件现场推导、诊断/退出/卸载入口。
尝试过但**不可行**的做法（别再重复）：
- 按类型搜索枚举边（Selection.Search "Type=Edge,all" 等）：语法不成立；
- Shapes.GetBoundary(标签) 取边界对象：调用失败；
- 用 Measurable 直接量 BRep 引用：不可用（只对特征与手动点选的命名单元有效）；
- 往正在运行的倒圆角命令里塞对象：命令不认（用真实鼠标点"确定"也不生效）；
- 按"编号偏移"猜对称边编号：不可行（BRep 编号按闭合环顺序，且每圈位移不同）；
- 在用户模型里试建"探针圆角"来识别边：**严禁**（删除失败会在用户模型里堆废特征，已实际发生过）；
- CAA（C++）方向：本机无可编译环境（无 RADE、无 VC8/VC9），**未编译、未验证**，只留了草稿代码。

【必须遵守的已知事实（已验证，别再试错）】
1) 命令运行中用户点选的对象不进 Document.Selection（Count2=0）；判断"用户选了什么"不要依赖它。
2) 交互式倒圆角命令不接受脚本加入的对象（列表为空、真实鼠标点确定也不生效）——不要试图往对话框塞元素。
3) 对话框列表可读：'凸台.1\目标边线.N'；FindObjectByName 可解析为可量测单元（长度+采样点）。
4) 读"真实 BRep 标签"的唯一可行办法：把该单元对象**本体**放进选择集，再读 SelectedElement.Reference.DisplayName；
   用 CreateReferenceFromObject 包一层再读会得到空字符串。
5) BRep 编号（Sketch.1;N）按"闭合环顺序"，与草图元素名（直线.N，创建顺序）不同；**每一圈各有一个循环位移**
   （实测：外圈 +3、内圈 +2）。位移必须**现场从用户点选边的真实标签推导**，且**只能在同圈内循环**。
6) 命令运行中创建的引用带 WithTemporaryBody，命令关闭即失效 → 顺序必须是"先读半径 → 先关命令 → 再造引用 → 再生成"。
7) 气泡按钮回调在新线程：必须 comtypes.CoInitialize()，且不要复用别线程的 COM 指针（每次重新取 ActivePart）。
8) 体积自检只能作为下限判据（相切传播会让体积变化远大于预估，不能据此撤销）。
9) 自动化无法枚举实体全部边：Selection.Search 类型搜索语法不成立、Shapes.GetBoundary 失败、Measurable 量不了 BRep 引用、
   命名单元只对手动点选的那条有效 → 形状级对称只能 CAA。
10) 任何识别动作都不得创建试探特征。

【必须实现的行为（验收标准）】
A. 点一条边 → 右键或 Ctrl+Alt+R → 自动找到对称边并生成**一个**倒圆角特征（半径取倒圆角对话框里的值，否则用配置默认值）；
   若有多解，弹选择框，选项按"目标边中点+长度"描述，不写"元素 a-b"。
B. 只保留轴对称（镜像）方案；中心对称/旋转默认关闭（配置可开）。
C. 误选到面时立刻提醒，可一键移除误选。
D. 连续作业：连续做 3~4 处圆角不失败（被削短的边用子段匹配）。
E. 换零件可用的判据：分圈、位移、匹配全部现场推导，日志给出
   '草图分圈结果' / '点选边真实标签索引=…，我们算的索引=…' / '同一圈内的编号位移 = +N' /
   '源边编号已按位移修正为 …' / '生成结果：ok=…'。
F. 安全阀：跨圈方案跳过；目标边"到零件中心距离"与源边不一致（>5% 或 >1mm）则否决；体积变化 <25% 预期则撤销；
   任何分支必须有异常日志 + 用户可见提示（不能静默失败）。
G. 便携版：单文件 exe + 文件夹模式；包内包含 启动/诊断/退出/卸载/取证 入口；诊断报告含类型库定位与加载测试、
   CATIA 连接、对话框识别、选择集判定；只读目录可用（配置/日志退到 %LOCALAPPDATA%）。
H. 卸载：两步确认（回车=确认、Esc=取消）→ 退出助手 → 删程序目录与数据目录；不写注册表、不改 CATIA 设置。

【交付物】
1) 源码（自动化版在 src\catia_fillet_assistant\；CAA 版在 caa\）；
2) 便携包 dist\（含入口脚本与说明）；

【测试与验收流程】
1) 单元测试（标签解析、几何映射）必须通过；
2) 在**临时测试件**上验证：100x60x40 凸台，两条竖直边 R5 → 体积 240000→239571 mm³（理论 429.2 mm³）；

4) 端到端：真实右键触发 → 关命令 → 生成 1 个含两条边的倒圆角；
5) 连续两刀验证（第二刀不得报"不是草图生成的边"）；
6) **所有会改模型的验证必须只在临时件上做**，绝不在用户文件上试。

【禁止事项】
- 禁止试探性建模；禁止往正在运行的命令里塞对象；禁止在用户文档上做任何实验性写入；
- 禁止把"某个零件的编号偏移"写死；禁止在没有异常出口的分支里调用 COM；
- 禁止在未验证的情况下声称功能可用（必须给出日志/体积等证据）。

> 上面只记录"试过什么、结果如何"；采用哪条路线由你自行判断，本文不预先限定。
```
