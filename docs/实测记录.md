## 2026-09-25 追加：命令内点选问题的实测与解法

现象（用户反馈）：在倒圆角对话框里选好边线后按快捷键提示"没有选中边线"，右键还弹出 CATIA 原生菜单。

实测结论：

1. 命令运行中，用户点选的对象**不会**出现在 `Document.Selection` 里（`Count2 = 0`）——
   被命令收进了自己的编辑器。所以助手先前"看选择集"的做法必然误判。
   （`FilterCorrespondence` 对空选择集会返回 True，也不能作为判据，已修。）
2. 对话框列表里能读到点选对象：`凸台.1\目标边线.1`；
   `Part.FindObjectByName("边线.1")` 能解析它，而且**能量到几何**：
   `Length = 20.0`、`GetPointsOnCurve` → `(0,40,30) (10,40,30) (20,40,30)`。
   注意：这种"名字"只对**手动点选**的对象有效，命令关掉就没了；宏加的对象不会被命名。
3. 反过来，**宏/自动化往运行中的命令里加选择集是无效的**：
   对话框列表仍为空、体积无变化、按确定不生效（试过 BM_CLICK / 回车 / SendInput 点击）。
   所以"往对话框里再塞一条对称边线"这条路在 V5R20 上走不通。
4. 可行解法：**读点选边的几何 → 推对称边的标签 → 用官方 API 直接生成倒圆角**。
   实测 `tools\test_autofillet_live.py`：
   100x60x40 凸台，源边 (100,0) 竖直边 → 对称边 (100,60) → R5 圆角后
   体积 240000 → 239570 mm³（正好等于两条 R5 圆角削掉的量）✔
   `tools\test_pair_fillet_live.py`（选择集 + 标签法 + R8）：体积 240000 → 238901 mm³ ✔
5. 特征树里"倒圆角.1"在**命令打开时就会创建**（进行中状态），所以之前用"形状数量 +1"判断"宏补线被接受"是错的，
   必须用体积变化或对话框是否关闭来判断。

## 2026-09-25 追加（v0.3.1）：编号错位导致的"点了却没选中对称元素"

用户反馈：有些点一下没选中对称元素；有些明明对称却识别不到。新日志（1224 行）显示：
①监视线程每轮都重新解析对话框单元 → 刷屏 1152 行并拖慢动作；②`没有找到对称边线`；③单元解析时好时坏。

用 `tools\probe_sketch_names.py` 打开发送方草图后真相清楚了：用户的草图有 **17 个元素**
= 1 条绝对轴 + **8 条直线** + **8 个构造点**（点.1…点.8，是画线用的端点）。

* 我原来的编号是"排除绝对轴后顺序编号"，把 8 个构造点也算了进去 →
  直线的编号变成 1,2,3,4,**9,10,11,12**，而 CATIA 的 BRep 标签用的是**直线自己的编号 1…8** →
  几何匹配虽然对上了，但生成对称边时引用的是**另一条边**（或直接解析失败）→ 就是"点了却没选中对称元素"。
* 修法：编号改用**元素名字里的序号**（`直线.4` → 4），构造点跳过不参与候选；
  修完在用户零件上只读验证（`tools\probe_label_path.py`）：
  外角(直线1-4) → 3 条对称边 (1-2)(3-4)(3-2)；内角(直线5-8) → (5-6)(7-8)(7-6)，全部解析成功 ✔
* 另外修了两处：单元名解析失败时兜底"扫描已命名单元取序号最大的那个（通常是刚点选的）"；
  监视线程改为"只有对话框内容变化才解析"，日志从 1152 行降到个位数 ✔
* 用户对话框里那条边（长 120）只读验证：源=`顶边(元素 1)`，得到 3 个对称目标（顶边3 / 底边1 / 底边3），距离全 0.0000 ✔

## 2026-09-25 追加（v0.3.2）：能不能"由助手把第二个元素填进倒圆角对话框"

用户希望：选好顶边后，对话框里自动变成"两个元素"。做了决定性实验（`tools\probe_dialog_fill.py`）：

* 命令开着时用脚本 `Selection.Add(边线引用)` ×2 → 对话框列表**始终为空**、体积不变；
* 再用**真实鼠标**点「确定」→ 对话框不关闭、体积不变 → **命令根本不接受脚本加的对象**。
* 结论：V5R20 的交互式倒圆角只认"手动点选"的对象，"脚本往对话框填元素"这条路走不通。
  可行的等效做法：①助手直接用官方 API 生成圆角（生成后双击特征树里的"倒圆角.x"，框里就是两条边，可随时改半径）；
  ②`config.json` 设 `symmetric_action: "select"` → 助手只把对称边加入选择集（在模型里高亮），你在对话框里点一下这条高亮的边即可。

## 2026-09-25 追加（v0.3.2）：凹槽/顶边相关的三个问题

1. **凹槽被误当成凸台**（`tools\probe_pocket.py` 实测）：`discover_names` 用 `Pad.1 + Sketch.2` 拼的标签竟然也能解析（CATIA 不校验草图归属），
   于是凹槽的边会按 `Pad.1` 去造标签 → 指向别的边。改为：先按本地化名映射（凹槽→Pocket、凸台→Pad…）排优先，
   **并逐个用"源边几何能否匹配候选"验证**，取真正对得上的那组名字。
2. **草图元素读不全**：用户草图里 8 条直线有 2 条（每个矩形的第 4 条）采样失败 → 映射缺失 → 对称边拼不出来。
   加了"动态派发再试 StartPoint/EndPoint"兜底 → 现在 8 条全部读到，编号 1..8 与 BRep 一致 ✔
3. **顶边/底边**：标签替换原来只换草图元素、不换端面，所以"顶边镜像成底边"永远拼不出来。
   新增：当对称变换把拉伸方向翻个（法向 w→−w）时，端面 1↔2 同步互换。

另外新增**体积自检**：生成圆角后比对体积变化与"半径×边长"的预期值，对不上就自动撤销该特征并报错（避免落在别的边上留下错的特征）。
