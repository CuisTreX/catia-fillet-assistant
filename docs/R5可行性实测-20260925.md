# R5/R14「形状级对称」可行性实测（2026-09-25）

> 结论先行：**R5/R14 在纯 Automation（Python + comtypes）上可行，不需要 CAA。**
> 依据：本次在 CATIA V5R20 上实测通过"枚举当前实体全部边 → 量几何 → 用扫到的 Reference 直接生成一个含两条边的倒圆角"。
> 但其中有三处必须写进算法，否则会静默出错（见 §3）。

| 项目 | 内容 |

## 2. 第一轮问题 A–G 的答案（全部有日志）

| 问题 | 结果 | 数据 |
| --- | --- | --- |
| A 能否枚举当前实体全部 Edge | **能** | `Selection.Add(MainBody)` + `Search("Topology.CGMEdge,sel")` |
| B 一共多少条 | **12 条**（100×60×40 凸台，完全正确） | 缺省 `Topology.CGMEdge,all` 得 16 条＝12 实体边 + 4 草图线 |
| C `Item2(i).Reference` 是否稳定 | **稳定** | DisplayName 形如 `Selection_REdge:(Edge:(Face:(Brp:(Pad.1;0:(Brp:(Sketch.1;4)))…` |
| D `GetMeasurable` 是否可用 | **可用** | Length = 60 / 100 / 40；圆弧还有 **Radius = 5.0** |
| E 能否取到 P0/P1/P2 | **能（有坑，见 §3.3）** | 3 点＝起点/中点/终点，如 `[0,60,0],[0,30,0],[0,0,0]` |
| F 圆角新边能否扫到 | **能** | 圆角后同一扫描出现 `TriDimFeatEdge` 长度 **7.853982 = πR/2 (R5)**，且直线边由 100 变 95、60 变 30 |
| G 扫到的对象能否当作 Fillet 输入 | **能** | 用扫到的两条 Reference 直接建出 `倒圆角.1`（一个特征含两条边），体积 0.00024 → 0.0002393562 m³ |

补充：`Topology.CGMEdge`、`Topology.CGMFace`（6 面）、`Topology.CGMVertex`（12 顶点）均可用；
而 `Topology.Edge,all`、`CGMEdge,all`、`Type=Edge,all` 均失败（与历史记录一致）。
**即：过去"自动化无法枚举实体全部边"的结论是语法用错了，不是能力不存在。**

## 3. 三个必须写进算法的坑（本次实测发现）

### 3.1 扫描范围：必须排除"草图线"，否则边数虚高

`Search("Topology.CGMEdge,all")`（不选任何东西）＝ 16 条，其中 4 条是 **草图 WireREdge**（类型名带 `MonoDim`、标签形如 `WireREdge:(Wire:(Brp:(Sketch.1;…`）。
正确做法：

```text
Selection.Clear() → Selection.Add(part.MainBody) → Search("Topology.CGMEdge,sel") → 过滤掉 MonoDim/Wire 单元
```

过滤后：圆角前 12 条、圆角后 18 条（＝当前 Tip 真实边数）。
另注：把"特征"（Pad.1 / 倒圆角.1）本身放进选择集再 `,sel`，拿到的是**该特征贡献的单元**（倒圆角.1 → 8 条），不是当前实体全部边；所以范围基准要用 `MainBody`。

### 3.2 自对称边（必须专门判据，否则必然误判）

垂直于镜像面或落在镜像面上的边，**镜像后就是它自己**（例：100 长边关于 x=50 镜像）。
第一版匹配器没有这一条时，凸台的三轴中面评分只有 0.5 / 0.667 / 0.5（假失败）；
加上"自映射即命中"后：圆角前 X/Y/Z 三面 → 10/12、11/12、10/12（剩余失败由 §3.3 造成），
圆角后 y=30 与 z=20 两面 → **8/8、8/8，误差 0.0**。

推论：候选匹配必须先算 `Mirror(E_source)` 与 `E_source` 自身的距离，
若 ≤ 容差，则"对称边就是它自己"——此时应提示用户"这条边本身就在对称面上"，而不是去别处硬找一条。

### 3.3 `GetPointsOnCurve` 会返回**不完整采样**（最危险）

实测：同一次扫描里，一条长 60 的边只返回了 2 个点 `[0,60,0] [0,30,0]`，折线长 30 ≠ 真实长 60（**只覆盖半条边**）。
这会静默导致"镜像后被判成差 30 mm"，进而在 12 条边的正方体上评出假失败。

必须加的校验（对应 Prompt §5 的降级链）：

```text
采样折线长 polyline_length 与 Measurable.Length 必须一致（相对容差 ~1%）
不一致 → 该边采样视为 INVALID → 走端点/顶点( CGMVertex )或 GetParamExtents+GetPointAtParam 的备用路线
```

测量到的可用事实：3 点采样时**确实是起点/中点/终点**，圆弧还能读到 `Radius`（5.0），
所以"直线 2 端点 + 圆弧 R/中心/轴"这套指纹是可用的，只是**必须校验完整性**。

## 4. 对《R5/R14 完整开发任务 Prompt》的评价

### 采纳（写对了的地方）

* §1 要求先验证 `Topology.CGMEdge`，不要用 `Type=Edge` 的失败当结论 —— **完全正确，本次已证实**；
* §2.1 禁止编号偏移、§2.3 禁止试探性建模（历史上 倒圆角.13…27 事故）、§17 生命周期、§24–25 子段匹配、§31–33 生命周期与线程、§44 全局对称≠每条边都有对称、§64 禁止伪成功 —— 都是必须保留的；
* §72「第一步只做只读 Edge Scanner」的顺序正确，本次即按此执行。

### 需要修正（照抄会踩坑）

| Prompt 处 | 问题 | 修正 |
| --- | --- | --- |
| §15 扫描流程 | 没说范围与过滤，按 `,all` 会把草图线算成边 | 用 `MainBody` + `,sel` + 过滤 `MonoDim`/`Wire` |
| §19–23 候选匹配 | 没有"自对称边"判据，必然误判 | 先判 `Mirror(E)≈E`（§3.2） |
| §5 / §37 指纹 | 假设采样可靠 | 增加"折线长 vs Measurable.Length"完整性校验（§3.3） |
| §62 体积回归 | 期望 ≈429.2 mm³（两边 R5） | 该值对应**不传播**；助手若用 `propagation=1`，实测 ΔV = 644 mm³（239356 mm³），不能当异常 |
| §3 架构 | 一次性拆 `shape_engine/ sketch_engine/ fillet_engine/ safety/ diagnostics/` + `config.yaml` | 与现有模块（`cellgeom/pairing/featuregeom/app`）重叠且改动面过大；建议先新增**一个** `edge_scan.py`，通过后再分拆；本机配置沿用 `config.json` 而非 `config.yaml` |
| §48–50 CAA | 把 CAA 写成"将来大概率要做的后备" | 本次实测后**当前没有必要**；只在后续遇到"某类新边取不到几何"时再启用 §66 判据 |

### 建议的实施顺序（改动最小）

```text
1. 新增 src/catia_fillet_assistant/edge_scan.py（枚举 + 过滤 + 采样完整性校验 + 指纹）  ← 本次已给出可运行原型
2. 纯数学单元测试：mirror_point / 自对称判据 / 线段子段匹配
3. 在现有 pairing.py 里接入"Shape Engine 优先，Sketch Engine 兜底"
4. 临时件端到端：Pad → 扫边 → 找对称 → 一个 Fillet 两条边 → 第二刀 → 第三刀
5. 负测试：非对称件必须返回 NO_CONFIDENT_SYMMETRY
```
